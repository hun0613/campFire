# 디자이너 시안 적용 (불멍 디자인 시스템)

디자이너가 보낸 요소 파일을 **원래 자리에 덮어쓰고**, 기준 캡처 · 동작 점검 · 실험실 점검으로 **바꾼 요소만 달라졌는지** 확인한 뒤 결과를 한국어로 보고한다. 커밋 · 배포는 하지 않는다 (사용자가 따로 말할 때만).

도구 폴더: `docs/디자인협업/도구/` (README.md 에 각 도구 설명). 로컬 서버 `npm run dev`(3000)가 켜져 있어야 한다. 꺼져 있으면 백그라운드로 켠다.

## 적용

1. **입력 확인:** 시안 파일 경로(여러 개면 하나씩), 디자이너 이름(없으면 물어보지 말고 비워 둔다). 파일 이름이 원래 이름과 다르면(예: `bench (1).js`) 사용자에게 어느 요소인지 확인한다.
2. **규칙 검사만 먼저:** `node docs/디자인협업/도구/check-element.mjs <파일>`
   - errors 가 있으면 적용하지 말고, 무엇을 고쳐 달라고 디자이너에게 전하면 되는지 한국어로 정리해 보고한다.
   - warnings 는 적용하되 보고에 적는다.
3. **적용 + 부작용 확인:** `node docs/디자인협업/도구/apply-design.mjs <파일> --name <디자이너>` 를 **백그라운드**로 돌린다 (약 10분: 적용 전 캡처 → 원본 보관 · 덮어쓰기 → 빌드 → 적용 후 캡처 · 비교 → 동작 점검 → 실험실 전체 점검). 빌드가 실패하면 스크립트가 원본으로 되돌린다.
   - 실행 중에는 `src/` 파일을 고치지 않는다 (개발 서버가 페이지를 새로 고쳐 캡처가 깨진다).
4. **결과 읽기:** 마지막에 나오는 report.json (기록 폴더 `docs/디자인협업/적용기록/<시각>_<이름>/`).
   - `changed`: 0.3% 넘게 달라진 장. **차이 그림(`차이/*.jpg`)을 Read 로 직접 열어** 빨간 곳이 바꾼 요소 자리인지 본다. 원래 흔들림(크리스마스 · 휴대폰 모닥불 · 처음 화면 0.3~1.7%, 주민 몸짓 · 빗방울)은 무시해도 된다. 도형 · 재질 수가 바뀌면 three.js 난수 때문에 주민 몸짓 · 빗방울이 달라지는 것도 정상.
   - 기준 캡처 자리와 그 자리에 보이는 요소: start(입구) · plaza(광장: 벤치 · 간판 · 화분 · 방명록) · fire(모닥불 자리) · lumi(루미 공방) · woodyard(장작 마당) · grandma(찻집 할머니) · lakebench(호숫가 데크 벤치) · reader(서연 · 작은 벤치) · hillbench(노을 언덕 벤치 · 고양이)
   - `perf`: 물체 · 면 · 재질 수 변화. 늘었으면 얼마나 늘었는지 보고 (휴대폰 부담).
   - `smoke`, `labBlank`, `consoleErrors`: 하나라도 문제면 원인을 찾고, 고칠 수 없으면 되돌린다.
5. **실험실 화면 확인:** 바꾼 요소를 `node docs/디자인협업/도구/labshot.mjs <폴더> <요소 id>` 로 찍어 Read 로 보고, 의도대로 보이는지 판단한다.
6. **기록:**
   - 노션 「🎨 디자인 점검 · 협업 현황판」(DB 421fcf3f621081dfb6d2c0976d4a09b5)에서 그 요소 행(id 칸)을 찾아 상태 `반영`, 반영 버전(`vX.Y.Z (준비 중)`), 담당(디자이너) 을 적는다. 행이 없으면 만든다.
   - CHANGELOG 의 「준비 중」 버전(없으면 새 패치 버전을 「준비 중」으로)에 한 줄: 무엇이 어떻게 바뀌었는지 + 디자이너 이름.
   - 디자인 협업 약정서대로 반영된 작업물의 디자이너는 게임 「만든 사람」에 넣는다 (크레딧 자리가 아직 없으면 보고에 「크레딧 자리 필요」라고 적는다).
7. **보고 (한국어):** 적용한 파일 · 달라진 곳(차이 그림 판단) · 성능 숫자 변화 · 동작 점검 · 주의 사항 · 기록 폴더. 끝에 「커밋할까요?」만 묻는다. 배포는 사용자가 「배포해줘」라고 할 때만.

## 되돌리기

「되돌려줘」면 `node docs/디자인협업/도구/restore-design.mjs <적용기록 폴더>` (가장 최근 기록이 기본). 빌드 확인 후, 노션 행 상태를 `검토 필요` 로 돌리고 CHANGELOG 줄을 지운다.

## 지키는 것

- 덮어쓰는 곳은 `src/elements/` 안의 같은 이름 파일뿐. 다른 파일은 시안 때문에 고치지 않는다 (시안이 다른 파일 변경을 필요로 하면 보고하고 묻는다).
- 시안 코드는 디자이너가 보낸 그대로 넣는다. 고쳐야 하면 고친 점을 보고에 적는다.
- `.env` · `docs/` 는 커밋하지 않는다. 보고 · 커밋 메시지 · 노션은 모두 한국어.
